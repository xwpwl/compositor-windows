# Compositor Windows 修图

用正在运行的 Windows 编辑器处理图像，让修改出现在用户的桌面画布中。软件是独立社区版，能力以当前工具 schema 和实际结果为准。

首次使用先按 [connection.md](references/connection.md) 安装整个 skill 文件夹并配置应用目录。分发包只提供 [local-config.example.json](local-config.example.json)，不包含本机路径或已注册的 MCP 连接；可复制为 `local-config.json` 后编辑，也可用 `-AppDir` / `COMPOSITOR_APP_DIR` 指定应用位置。

## 连接与选定文档

- 若已配置 MCP，优先发现并调用 `compositor_windows` 的五个工具：`compositor_get_state`、`compositor_get_canvas`、`compositor_open_image`、`compositor_edit`、`compositor_export`。命名空间可能不同，按工具名查找。
- 当前聊天未加载这些工具时，用本 skill 随附脚本连接软件原有 MCP 服务，见 [connection.md](references/connection.md)。这仍是在实际桌面程序内编辑，无需为了本次操作修改全局配置。
- 先读状态并看画布。优先复用已确认属于本次目标的文档；多个同名标签用文档 ID 和预览区分。打开新图片会新增文档；合成素材用 `asLayer:true`。
- 软件未运行时，按连接说明启动可见窗口，再读状态；不要在已有连接但请求失败时反复启动新实例。保留用户其他文档和未保存修改。

## 根据画面编辑

把用户明确要求保留的主体、完整身形、文字或构图作为约束。比如“保留中间的人”，检查头部、手部、双脚和边缘余量；不要把上一张图的全景裁剪、方形比例或调色参数固定套用到下一张。风格未指定时可先做克制的自然调整，说明主要取舍并继续执行。

每轮按“看画布 → 编辑 → 再看画布”工作。预览坐标必须换算为当前文档坐标：`x_doc = x_preview × document.width / preview.width`，Y 轴同理。使用工具实际返回的预览尺寸，不把聊天缩略图尺寸当原图尺寸。裁剪后重新读状态，后续坐标以新文档原点为准。

具体动作与参数见 [editing.md](references/editing.md)。操作时注意：

- 使用真实文档/图层 ID；需要确定目标时显式传 `layerId`。部分图层动作会切换活动层，不能依赖旧的选中状态。
- `crop` 只改变画布范围和图层偏移；`adjust` 保留可编辑参数。对单张大照片，通常无需为这两步复制整张像素图层。
- `adjust` 作用于整层，选区不会限制调色。只提亮人物等局部任务，使用带局部蒙版的副本层，具体步骤见编辑参考；不要给唯一原图层套人物蒙版而隐藏背景。
- 将相关且兼容的动作放入一次 `batch`，便于整体撤销；批处理不能包含导入、导出、新建/切换文档、撤销/重做或嵌套批处理。
- `paint`、`fill`、`filter` 默认改像素。修改蒙版必须明确 `target:"mask"`，先确认蒙版存在。蒙版按 alpha 隐藏内容：擦除隐藏，白色普通绘制恢复；涂黑不等于隐藏。
- 当前去背景是边缘连通纯色算法，不是人物/头发分割。复杂路人移除、生成式补全、液化或 RAW 处理不能假称已经支持。需要改用其他工具时先明确实际限制，并遵循用户对软件的选择。
- 8K 图像的调色和预览仍会处理完整像素；裁剪不会降低底层内存占用。历史有内存预算，大图可能只能保留少数步骤。避免无意义复制层和重复全尺寸预览。

## 检查与交付

查看最终画布，确认主体保留、裁剪边界、颜色、文字和透明边缘符合请求。普通修图无需每次执行完整回归测试；用户要求测试流程、首次接入或发生故障时，再验证撤销/重做和工程读回。

按用户指定位置输出；未指定时使用当前工作区的 `outputs/`，中间预览放 `work/`。创建输出目录，并选新文件名，除非用户明确要覆盖；保留输入原图。

- 照片成片导出 `jpeg`（扩展名 `.jpg`），透明图导出 `png`；继续编辑的版本另存 `.cwdoc`。
- MCP 导出 `.cwdoc` 不会自动清除原标签的未保存标记。以成功返回、文件存在和必要时的读回为证据，不把 UI 标记当作导出失败。
- **MCP 导入上限 45 MiB**，与磁盘实际文件大小比较。超过上限的图像或工程使用软件原生“文件 → 打开”；有 Windows Computer Use 能力时按其技能操作，否则说明需用户打开。原生打开后，MCP 仍能读取和编辑。不要通过提高上限或再次 base64 编码绕过现有传输约束。
- 工程读回要核对文档尺寸、图层/调色参数和实际预览。不能仅凭文件写出成功就声称已经验证读回。PNG 预览用相同尺寸和相同状态才可比较；JPG 有损输出不要求与画布字节一致。

完成后展示实际输出预览，链接成片与工程，简要说明做了什么以及仍影响结果的限制。桌面保留用户可继续操作的结果文档。

## 故障恢复

请求超时不代表编辑已回滚。停止追加变更，先读状态、查看画布/提示，再决定下一步；不要自动重发同一裁剪、画笔、批处理或导出。若读状态仍失败，检查桌面是否忙碌或等待对话框，保留现场并说明阻塞点。连接、文件大小和原生对话框的具体处理见 [connection.md](references/connection.md)。
